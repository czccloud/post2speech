# RUNBOOK — A/B 盲测执行规程

A/B 盲测用来验证一次**重要规则变更**是否真的有效（见根 `README.md` 辅助迭代手段第 3 节）。它回答的是"人盲选时真的更喜欢新版吗"，和回归测试（`../regression/RUNBOOK.md`，回答"有没有改坏旧场景"）互补，不互相替代。

## 触发时机

- 结构性改动、禁用清单大改、多条款联动的版本升级 → 建议跑。
- 单条规则的微调（如补一个例子、一句限定）→ 不用跑，回归即可。
- 宣称一轮重要迭代收敛前 → 建议跑，作为"人耳"维度的证据。

## 执行步骤

1. **生成**：同一输入、同一生成条件（同模型、同任务要求），分别加载变更前/后的规则文件生成两版输出。任务要求统一写死，只输出改写结果，不带解释。
2. **封存**：打乱两版输出标注为 A/B，把分配明文加上随机 nonce 算 SHA-256，**先把哈希记进记录文件**，再给人盲选。揭晓后附明文重算验证（做法沿用 ab-tests/20260910-01 的封存承诺惯例）。这一步是为了让"打乱"可被事后验证，防生成方有意无意按偏好排序。
3. **盲选**：盲测人在不知道对应关系的情况下读 A/B，选出哪版更像人话，或判"无明显差别"，先填「盲选结果」再填「揭晓」。盲测人不得参与当次 A/B 的生成。
4. **揭晓**：填对应关系、验证封存承诺、按下方判定规则写结论。

## 判定规则

单次单样本的盲选**不作定论**（20260910-01 的教训：一次"变更无效"可能只是题材或篇幅差异）：

- 同一次变更，至少跑 3 个不同题材的输入（用 `../corpus/` 固定输入），汇总进 `summary.md`。
- 胜率 ≥ 2/3 → 判"变更有效"；败率 ≥ 2/3 → 判"变更无效"，回 CHANGELOG 评估是否回滚；其余 → "不确定"，加样本再判。
- "无明显差别"不计入胜也不计入败，计入样本数。
- 判"无效"的变更，回滚前先用真人朗读 + ASR 定位偏好来源（语气词密度、篇幅、视角），不凭单次盲选直接动规则。

## 归档纪律

- 每次盲测按 `TEMPLATE.md` 存为 `YYYYMMDD-NN.md`，已归档记录不改。
- 每次跑完在 `summary.md` 追加一行，累计胜率看趋势。
- 盲测结论涉及规则回滚或确认变更有效时，在 `CHANGELOG.md` 对应条目里补一句引用。
