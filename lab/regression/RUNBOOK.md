# RUNBOOK — 测试执行规程

每次修改 `references/` 下任一规则文件（`core.md` 或 `overlays/` 下文件）后，以及在宣称一轮迭代收敛之前，必须按本规程完整跑一遍测试，并把结果归档到 `results/`。禁止口头宣称"已通过""已收敛"（对应根目录 `AGENTS.md` 禁止事项第 2 条）。历史用例的「关联规则」字段若指向 `references/kimi-k3.md`、`references/glm-5.3.md` 等旧路径，这些文件已移入 `references/legacy/`，对应条文均已并入 `references/core.md`，判定时按 core.md 中的同编号规则执行。

## 触发时机

- 修改了 `references/` 下任一规则文件 → 必跑（用触发本次校准的那个模型跑）。
- 一轮迭代准备收尾、准备宣称收敛 → 必跑，且需同时满足根 `README.md` 收敛标准的三条。
- 只动了 `lab/corpus/`、`lab/ab-tests/`、文档，没动规则文件 → 不用跑。

## 第一步：corpus 题材覆盖测试

1. 加载当前规则主体 `references/core.md`（被修改的是 overlay 时，叠加该 overlay）。
2. 逐段改写 `lab/corpus/` 下全部输入（每个题材文件里所有非占位段落，占位段跳过）。
3. 逐题材对照检查：输出相比上一版规则文件生成的输出，是否出现新的书面腔、断句变长、语气词消失、禁用清单词回潮等退化迹象。有上一版归档输出的（见 `results/` 历史记录），直接对比；没有的，按当前规则文件自检清单逐条过。
4. 每个题材给一个结论：无退化 / 有退化（附具体句子）。

## 第二步：regression 负样本回归

1. 列出 `cases/` 下全部**状态为"活跃"**的用例（已作废的跳过）。
2. 逐条执行：用当前模型的规则文件改写用例的「输入」。
3. 对照用例的「问题说明」和「关联规则」，按三级判定：

| 判定 | 标准 |
|------|------|
| 通过 | 输出不再出现「错误输出」中的同类问题，且不违反「关联规则」 |
| 复发 | 输出再次出现「错误输出」中的同类问题（病根相同，字句不必一致） |
| 疑似 | 同类问题没有完整复现，但出现了沾边的迹象（如并列项拆了但回环结构丢了）。疑似不算通过，也不算失败，必须标记出来交人耳确认 |

4. 注意判定的是"同类问题"，不是逐字比对。「错误输出」是历史快照，当前输出字句不同是正常的。

## 第三步：差异率联动

- 本轮如果是校准时（有 ASR 转写或真人确认数据）：差异率记进校准记录，并追加到 `../calibration/metrics.md`。
- 本轮如果只是规则改动后的回归（没有新校准数据）：不新增差异率记录，但要在结果归档里写明最近一次校准的差异率，作为参照。

## 第四步：归档结果

按 `results/TEMPLATE.md` 填写，存为 `results/YYYYMMDD-模型-版本.md`（如 `20260910-kimi-k3-v1.2.md`）。

- 全部用例通过 + corpus 各题材无退化 → 结论"可收尾"。
- 任何用例复发或题材退化 → 结论"需修复"，先修复再重新跑一轮，不允许带失败收尾。
- 有"疑似"项 → 结论里列出，等人耳确认后才算闭环。
