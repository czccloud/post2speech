# post2speech

把书面文字（帖子、文章、讲稿）改写成**适合口语朗读**的 Skill。目标不是"读起来通顺"，而是"读出来像人说话"——有自然的停顿、语气、节奏，没有书面语的生硬感。

## 仓库结构

```
post2speech/
├── README.md            # 本文件：方法论与结构说明
├── AGENTS.md            # AI 参与迭代时必须遵守的守则
├── SKILL.md             # 路由：按当前模型分发到 references/ 下的规则文件
├── references/          # 核心产出：分模型的口语化改写规则（GLM 5.3、Kimi K3，各自独立迭代）
├── CHANGELOG.md         # 规则归因日志：每条规则从哪次差异来
├── corpus/              # 固定测试输入集（多题材，用于回归测试）
├── calibration/         # 每轮朗读校准记录（AI 原文 + ASR 转写 + diff 归因）
├── regression/          # 负样本库：典型 bad case 与期望输出
└── ab-tests/            # A/B 盲测记录
```

## 核心迭代方法：朗读校准循环（Read-aloud Calibration Loop）

这个 Skill 的规则不是一次写成的，而是通过"AI 写 → 人朗读 → ASR 记录 → 对比差异 → 回写规则"的循环逐步校准出来的：

```
┌─────────────────────────────────────────────────────────┐
│  1. 生成：让 AI 用当前模型的规则文件改写一段内容             │
│                       ↓                                 │
│  2. 朗读：人用自己的口语习惯自然地朗读这段话                │
│          朗读时允许即兴修改——改得顺嘴就是对                 │
│          朗读过程录音                                      │
│                       ↓                                 │
│  3. 记录：用 ASR（如 Whisper）把录音转写成文字，            │
│          得到忠实的"实际朗读版"，包含：                    │
│          - 停顿：在哪里断了、断了多久                      │
│          - 语气：哪里上扬、哪里加重、哪里放缓               │
│          - 标点：书面的标点 vs 实际换气/节奏点              │
│          - 冗余词：口头自然加入的"那个""就是说""其实"        │
│          - 即兴改写：读不顺的句子被顺口改成了什么样          │
│                       ↓                                 │
│  4. 对比：AI 原文和 ASR 转写版放在一起，                   │
│          让 AI 逐条分析差异，归因到具体规则缺失             │
│          记录存入 calibration/                            │
│                       ↓                                 │
│  5. 集成：把可复用的差异规律提炼成规则，写回该模型的规则文件 │
│          同时在 CHANGELOG.md 记一条归因日志                │
│                       ↓                                 │
│  6. 回归：用 corpus/ 和 regression/ 跑一遍，               │
│          确认新规则没有改坏旧场景                          │
│                       ↓                                 │
│  7. 循环：换一段新内容回到第 1 步，                         │
│          直到朗读版和 AI 原文几乎没有差异                   │
└─────────────────────────────────────────────────────────┘
```

### 关键原则

- **ASR 转写稿是真理来源**。不靠人脑记忆朗读版，记忆会失真；录音转写忠实保留冗余词、断句和改口。凡是"写出来但读不出口"的表达，都是 Skill 需要修的规则。
- **差异要归因，不要只改个案**。每次对比后提炼的是"这类结构都要这样处理"，而不是"这句话改成那样"。
- **每次换题材测试**。说明文、故事、评论、技术内容的口语节奏不同，单一题材会过拟合。
- **规则按模型分开校准**。同一套规则在不同模型上效果不同；`references/` 下每个模型有自己的规则文件，迭代哪个模型就只改哪个文件，不跨模型同步。
- **Skill 越短越稳**。规则只留反复被触发的，长期没用的要删。

## 辅助迭代手段

### 1. 负样本库（`regression/`）

每次发现"AI 写得不口语"的典型 bad case，存一条用例：`输入 → 错误输出 → 期望输出 → 关联规则`。每改一版模型规则文件，把整个库跑一遍，防止修了 A 问题、把之前调好的 B 场景改坏。这是防止迭代来回震荡的关键机制。

### 2. 规则归因日志（`CHANGELOG.md`）

每次 diff 后不只把规则写进该模型的规则文件，还要记一条日志：`模型名 → 哪类差异 → 加了/改了哪条规则 → 源自哪次校准记录`。迭代几轮后回看日志，能看出哪些规则反复被触发（核心规则），哪些从来没用过（可删除）。

### 3. A/B 盲测（`ab-tests/`）

同一输入，分别用旧版和新版规则文件生成两版输出，打乱顺序标注为 A/B，让人盲选哪版更像人话，再揭晓。避免"我知道改了什么所以觉得新版好"的确认偏误。用于验证一次重要规则变更是否真的有效。

### 4. 多人朗读交叉验证

一个人校准出来的 Skill 只适合自己。找 1-2 个朋友按同样的校准循环朗读同一批内容，对比差异：

- **共性部分**（所有人都改的地方）→ 通用口语规则，写进该模型规则文件的主体。
- **分歧部分**（因人而异的地方）→ 做成规则文件里的风格开关，不写死。

## 测试方法

| 测试 | 做法 | 作用 |
|------|------|------|
| 题材覆盖测试 | 每版规则文件都在 `corpus/` 的固定输入上跑一遍 | 防止某类题材退化 |
| 负样本回归 | 每版都跑 `regression/` 全部用例 | 防止旧问题复发 |
| 差异率指标 | 统计 ASR 朗读版与 AI 原文的编辑距离/改动处数量，逐轮记录 | 用数字看收敛，不靠感觉 |
| LLM 评委 | 用另一个 AI 按"口语化程度/停顿合理性/有无书面腔"打分 | 快速筛出明显退步（不能替代耳朵） |
| TTS 端到端 | 把输出喂给 TTS 引擎听效果 | 最接近真实使用场景；TTS 读不顺的地方就是 Skill 的测试信号 |

## 收敛标准

- 连续多段**不同题材**的内容，ASR 朗读版与 AI 输出的差异趋近于零（朗读时不再需要即兴修改）；
- `corpus/` 和 `regression/` 全部通过；
- 差异率曲线持续平稳在低位。

三者同时满足，才算这一轮迭代收敛。
